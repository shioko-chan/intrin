# Site layout and deployment

These facts were checked on 10 October 2026. Recheck the source and Cloudflare Pages settings when using the skill later.

- Source is the public GitHub repository `shioko-chan/intrin`, production branch `main`. Cloudflare Pages project `intrin` is connected through its native Git integration. It runs `npm run build:release && npm run check:release` at the repository root with no framework preset and publishes `release/`. `.node-version` selects Node.js 22.16.0. Changes to `main` trigger a Pages build and deployment. The project URL is https://intrin.pages.dev/; verify whether `intrin.org` has been attached before reporting that domain as updated.
- This dependency-free Node static site renders from `content/en/site.json`, `projects.json`, and `updates.json`. `public/` contains styles and existing media. Generated `dist/` is for local preview; generated `release/` is the Pages output. Both are excluded from Git.
- projects.json has stable ids llcl, sketchvla, and skymerge. A project's updateId selects its featured note. updates.json records have id, projectId, date, draft, type, title, summary, intro, verified, ongoing, and next. The builder sorts notes newest first; the homepage shows the first three. Keep every note draft: true under the current site convention. Dates on draft notes denote preparation, not a new result.
- Existing videos, mosaics, captions, and evidence limits should be preserved unless an approved evidence-backed change requires them. Inspect the current source and media before editing those claims. Any external evidence material belongs outside the public repository unless the user separately approves its publication.
- npm run build generates dist/. npm run check checks links, media, noindex, draft flags, and an external URL allowlist. A new public link needs evidence review and an intentional check-rule update; do not bypass the check. npm run preview binds to 127.0.0.1:4317 and serves dist/ only.
- `npm run build:release` and `npm run check:release` prepare and validate the Pages output. The release still includes draft labels and noindex controls. Do not bypass a failing check to publish.
- The build copies only `public/` and rendered pages. Keep reports and review notes outside `public/`, `dist/`, `release/`, and the public Git repository. The bundled draft helper copies only build inputs into a temporary directory; it does not commit, push, or deploy. GitHub branches and Pages previews can be public, so keep unapproved drafts local.
